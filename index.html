Project Overview

Premise

PropertyPixel Studio is an AI native SaaS product built through a solo, founder led development process, with design entering as a single embedded function without a team structure for peer review. Minimal early usage data meant product direction relied primarily on founder sign off and direct competitive positioning rather than established metrics.

Approach

Conversion was the initial priority, benchmarking the landing page and demo against competitors while usage data remained limited. As session recordings and user analytics accumulated through PostHog, the approach shifted toward structured audit work on the core studio workflow, relying on direct observation and usability heuristics in the absence of statistically significant patterns.

Decisions

Nine interface decisions were shipped, aimed at increasing usability, reducing friction, reinforcing customer trust, and improving clarity around system behavior. Studio level changes were the most substantial, extending beyond static layout into interaction design, addressing batch level production workflows in an area where the product needed to support real complexity without overwhelming the user.

Each of the following decisions is documented individually, showing the before and after state, the issue identified, and the reasoning behind the change.

Context

Conversion was low, which led me to conduct competitor research. I found every comparable product led with visual proof in their hero section. PropertyPixel had an interactive demo, but it was left unseen unless scrolled, and the "Try the Studio" button led to an elaborate product demo but read as another signup path rather than an invitation to look deeper.

Context

This was a user's first interface with the studio before signing up, so it needed to feel premium and purposeful even without upload access. Sidebar icons had no labels, and the toggle controls above the image caused the viewport to resize and glitch on interaction. The disabled "View Only" button became an active "Enhance 5 Photos Free" CTA, turning that first impression into conversion.

Context

Mobile carried the same disabled-CTA problem as web, plus two more: the enhance action was buried in a secondary "Tools" tab, and there was no way to see which image was selected before enhancing. The redesign surfaces enhance as a primary CTA, adds a visible, selectable image list, and activates the CTA.

Context

Credits led with raw numbers and four competing buttons, cancel included, before a user understood what they had. The redesign replaces the numbers with a usage graph, states what credits are worth, and moves detail actions behind a quiet link so cancel isn't the first option offered.

Context

Subscription cards read identically regardless of tier: the active plan's CTA matched its neighbors, "Downgrade" felt punitive, and the premium tier carried no visual signal. The redesign enlarges the active CTA, softens "Downgrade" to "Switch to Starter" with a per-card billing toggle, and introduces purple as Studio's dedicated premium cue.

Context

The AI suggestion popup appeared directly in the main viewport for every uploaded photo, sitting in front of the image until a user actively dismissed it. Moved into the enhancement panel instead, with a glow effect marking the AI-selected options and accept/deny still available, so the suggestion informs the workflow rather than interrupting it.

Context

Processing feedback was fleeting: a small "in progress" card buried under the fold, and a status overlay that covered the primary CTA for a few seconds before disappearing entirely, there was no way to check what had processed or find it again. The redesign replaces both with a persistent panel tracking every enhancement in the session, queued or complete, one click away via View.

Context

Batch selection required users to remember which images needed enhancement, since clicking a thumbnail selected it without preview, and only original images could be added at all. The redesign keeps selected images visible as they're added, opens selection to enhanced images too, and introduces a floating panel that tracks the growing batch, each entry removable, up to 10.

Context

The download list mixed enhancement names, ambiguous project labels, and original images the user already had, reading as clutter rather than a clear choice. The redesign groups everything under each photo's filename as a subheading and adds a preview mode, so a specific version can be viewed, and downloaded alone, before committing.

Reflection

This project reframed how I think about design maturity, recognizing that different products, and different stages of a product, call for different kinds of attention. Rather than defaulting to aesthetic polish, most of the meaningful work here was functional and systemic, improving how the studio behaved rather than how it looked. Working through batch selection and processing visibility also pushed my thinking from static hierarchy into genuine interaction design, how a system reveals and paces information over time, not just how it's arranged. Without a team to critique against, much of this judgment had to be trusted and defended on its own, reinforced by an ongoing, iterative process where new features shipped nearly every week and not every idea made it into the final release the way I'd envisioned it.
